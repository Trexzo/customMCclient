# Focused parity assessment: divergent historical PR #467, original World source ownership

**Date:** 2026-10-25. Target: certified V324 `060445b541f7b83b975d3311683e7778a431bf0e`, with unchanged relevant source in double-certified V325 `55aef8aeaae76b3345c1e03c7bf8d21aaf1d8540`. **Read-only source review:** not a commit transplant, new native experiment or claim of byte-identical behavior.

## What original PR #467 actually added

Historical source PR [#467](https://github.com/Trexzo/customMCclient/pull/467) introduced `Minecraft189ScaffoldWorldOwnership`, a **per-host** strong-reference owner of `Minecraft189ScaffoldWorldReadAccess` with a monotonically advancing generation, plus an accessor `host.scaffoldWorldEvidence()`. `observe(world)` revoked previous World evidence when World identity changed; `observe(null)`, host close and unreadable source failed shut. Its three tests checked per-host lifecycle, disconnect/reconnect minting a new epoch, and native errors returning UNKNOWN. The acceptance flag `custommc.acceptance.requireNativeScaffoldWorldCell` printed a historical epoch-owned marker after observing a World through `HostRuntime.worldEntityPositions`.

**Important:** That historic class, accessor, test and exact pass marker are absent under those exact names in V324/V325. Do **not** assert literal API/test/marker parity.

## What the cumulative code now does instead

1. **`Minecraft189ScaffoldWorldLease`** provides a callback-scoped current original World reference and monotonic epochs for the native support planner. `open(world)` invalidates the prior `Minecraft189ScaffoldNativeWorldEvidence` immediately; `choose(world,...)` rejects a different instance, stale generation, missing/nonfinite input or invalid/closed lease; `invalidate()/close()` revoke old evidence. The `Minecraft189ScaffoldWorldLeaseTest` directly exercises new World after old lease, stale evidence rejection, read exceptions, null source, close and no post-callback world reads.
2. **`Minecraft189ScaffoldActivationSource`** weakly witnesses the exact original Minecraft/World/Player tuple per Scaffold activation. After initial World capture, a missing/replaced/collected source yields irrevocable `REVOKED` until a new module activation. The production `Minecraft189RuntimeBridge.originalScaffoldContextAtTick` disables the module controller on revocation; a GUI owner also disables it.
3. **`Minecraft189ScaffoldSourceEpoch`** independently observes weak Minecraft/World/Player identity **only when an original placement candidate or receipt is pending**, rejects absent sources, never wraps epochs, and requires same generation before and after the real World/inventory readback. The pending receipt retains primitive metadata and epoch rather than game objects. It is described as *acceptance-only source receipt*, not a substitute for production activation guard.
4. **`Minecraft189WorldEntityHostSourceLease`** extends `Minecraft189ExactSourceLease` for original loadedEntityList getter callbacks, independently of Scaffold. A different/null nested source irreversibly revokes the enclosing getter stack and its published position/UUID evidence before the callback returns. `Minecraft189WorldEntityHostSourceLeaseTest` includes nested same/different World, null, exception, stale snapshot and restart-after-exit cases.

## Parity decision

- **Safety goals visibly retained or strengthened:** exact World identity (not hash/dimension/index); new source cannot borrow old lease; stale native World evidence becomes unavailable; null/disconnect/native read error fails closed; module activation ends on World/Player swap; original controller placement receipt cannot be certified by a later World.
- **Architecture is materially different:** original #467 provided a long-lived per-host native *World-cell evidence accessor*, whereas current planner uses a callback-scoped World lease, separately strict production activation and acceptance receipt controls. Original acceptance marker and per-host generation API are not reproduced 1:1. The modern callback scope is *narrower*; absence of the old accessor does not itself demonstrate a missing live protection.
- **Not established:** a formal temporal refinement proof for every old `observe` interleaving, exact historical marker parity, or that all possible consumers of the old `host.scaffoldWorldEvidence()` would have identical behavior. These would require a separate explicit requirement and new acceptance tests; **do not silently resurrect that API** just to reconcile Git history.
- The certified cumulative V324 had independent 2×80/80 real Mojang Minecraft 1.8.9 + dedicated vanilla server attempts, and V325 independently did too. Neither run is a mathematical equivalence proof of old #467.

**Action:** classify #467 as **architecturally superseded for live native World ownership safeguards; exact old per-host API/marker is intentionally absent and not certified equivalent**. No cherry-pick or production source change recommended on present evidence. Keep historical branch Draft, defer any extra tests until a concrete unmet requirement or native failure exists. Preserve #503 and all original CI negative gates. **No main merge or release.**
