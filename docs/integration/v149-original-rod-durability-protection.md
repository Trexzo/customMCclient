## Production option
Persisted Combat ClickGUI **Protect Rod Durability**, `combat.autoRod.protectRodDurability`, **false by default**; **Minimum Rod Durability**, `combat.autoRod.minRemainingDurability`, integer 1..64, default **3**. With protection enabled:
- Read only the actual original Minecraft 1.8.9 source ItemFishingRod item type, positive ItemStack count, valid `ItemStack.getMaxDamage()` and `getItemDamage()`, and remaining uses `maxDamage-itemDamage`. Reject unknown/invalid source metadata and real original rods below configured minimum. Never select or dispatch an invalid rod.
- With **Auto Detect Rod Slot** enabled, skip the worn original held rod and continue scanning for a viable original source hotbar rod. The original default held-first/lowest-slot search remains among *eligible* rods. Existing V135 `Prefer Durable Rod` still ranks by highest remaining genuine source durability, breaking ties by held then earliest real slot; the new filter composes with that option. With fixed slot configured, only the configured original source item may be used; do not fall back into an unconfigured slot when it is worn.
- Do not consider item names, fabricated durability, translated enchantments or server-side fishing results as authority. With both new settings disabled, original AutoRod selection and cast behavior are unchanged.
- Source callbacks can replace original ItemStack wrappers or mutate damage/count/currentItem. The new strict positive source durability check reads mapped max and item damage twice around original selected-array membership checks and native ItemStack class/count/held item witness. Re-check **immediately before** original Mojang `Minecraft.rightClickMouse()` along with V129–V143 captured item and hotbar owner. A now-worn source rod or GUI threshold/mode change revokes use, does not commit a cooldown, and the existing finally restores only the originally owned user slot.
