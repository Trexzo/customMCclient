# V236 — NoClip genuine native collision getter/setter and baseline owner

NoClip is not a simple boolean motion command: the module captures the actual source player's original `noClip` baseline, forces true only for that original player, and must later return the original false (or preserve an originally true baseline). Its previous epoch and baselineOwner checks prevented ordinary respawn/World changes but did not guard *synchronous nested host callbacks* from the mapped `customMcNoClip()` getter and `customMcSetNoClip(...)` setter. A nested call using another original player during first-baseline capture could replace the owner's baseline before the outer getter returned. A nested same-player ClickGUI/sneak veto during a setter could leave the already-applied collision override true after menu focus.

V236 pins the entire real native capture/force/restore callback to one player through `nativeNoClipDispatching` with a `try/finally` lease. Any other player or null native source in a nested callback revokes old ownership without reading/writing the new player. A nested same-player real menu, disabled module or configured but invalid sneaking evidence revokes the old force; after a *successful* mapped original setter whose true already reached the player, release the owned boost through the existing original baseline restore, only when the exact original player and epoch still qualify. Genuine native getter/setter exceptions are never treated as completed writes and never trigger a synthetic restoration. Preserve the existing same-player OFF→ON baseline-retention behavior and avoid overwriting a newer activation; retain independent original baseline true and actual GUI/sneak release. A revoked restore never discards the still-pending original lease for subsequent source callbacks.

New Java 8/JUnit adversarial original-shaped tests cover same/different player getters/setters, first native baseline capture, nested ClickGUI/sneak/disable, actual disable restore, source exception, original true-baseline ownership, OFF→ON preservation, and world swaps. Source adapter tests alone are not authentic Mojang verification. Require exact V236 Windows and Ubuntu Foundation, full original pinned Minecraft 1.8.9 graphical X11 and vanilla dedicated server 78-step acceptance, then an independent unchanged-SHA rerun.
