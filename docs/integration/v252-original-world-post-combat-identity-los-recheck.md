# V252 — Revalidate original UUID order and LOS *after* native combat getter

V249–V250 pinned one original World object across LOS/UUID/XYZ and Kinds/Combat host calls, and V250 validated exact UUID and LOS snapshots *before* `customMcLoadedEntityCombatStates()`. That did not detect a loadedEntityList reorder or LOS change performed synchronously **inside** the combat getter of the very same original World object: the previously accepted positional identity could become stale before combat or target selection was published. A World reference lease alone cannot prove a list-generation invariant.

V252 reuses the existing exact UUID and LOS equality policies in a private `originalWorldCombatEvidenceStillConsistent` helper and calls it BOTH before and after the genuine native combat getter. Exact UUID list ordering is compared to the original identity snapshot, not merely membership or length; original LOS must still exactly match the original visibility snapshot when WallCheck is active. Both post-read checks are conditional: neither a UUID native read when `identityRequired()` is false nor an LOS read when WallCheck is disabled. If the checks fail with the same original World, combat/nearest/aim target and remembered KillAura lock are cleared, preserving the original V250 fail-closed policy. If a nested callback replaced the World source, the existing complete world-source invalidation is used instead. Genuine native read exceptions in optional UUID/LOS checks still fail closed, not promoted to a hard exception; native combat getter exceptions still propagate. No source data, UUIDs, target, or visibility is fabricated, and source lease / map / module behavior outside this evidence boundary is unchanged.

**Remaining limits:** The stronger two-point check detects changes visible in original UUID/LOS at the end of the combat getter, but cannot prove the list remained stable if it changes and restores in between checks (ABA), or when identity/WallCheck evidence is not enabled. An authoritative native loadedEntityList generation ID would be required for those cases. No claim that the original FOV/locked-target CI failures were caused or cured by this change. No Combat/Render standalone source code is modified.

Exact-head Windows and Ubuntu Foundation, full pinned genuine Mojang 1.8.9 graphical X11 + vanilla-server 78-step gate and a second independent unchanged-SHA run remain mandatory. Stacked Draft child of V251; preserve all existing tests, historical failures, and unchanged main.
