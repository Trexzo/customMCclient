# V245 — Atomic original ground/sneak/sprint player sampling

The original host `playerMovementState` called `EntityPlayerSP.onGround`, `isSneaking()`, and `isSprinting()` as three independent mapped native getters, publishing all three to a shared snapshot used by Freeze, movement jumping, timer, mining, NoClip, and other policies. Any one mapped original getter can synchronously reenter HostRuntime with a different original player or a null world-unload source. Without source pinning the former player could publish its stale grounded/sneaking/sprinting state AFTER a replacement was observed, and later modules could reuse wrong-source motion eligibility.

V245 introduces `Minecraft189MovementSnapshotSourceLease` and pins one original `Minecraft189PlayerMovementStateAccess` for all three mapped reads. Nested same-player callbacks never create another source tick. Nested changed/null original player revokes the outer lease irrevocably. Validate ownership **after EACH genuine getter** and publish only a complete three-value observation from the exact source; otherwise CLEAR the shared snapshot rather than create a partial/stale one. Original null callback continues to clear. Genuine original getter exceptions propagate, but clear stale previous state first; try/finally releases lease. A new real callback after the stack unwinds may establish a legitimate new player's state.

Do not invent ground/sneak/sprint values from movement keys or GUI state; no changes to Combat/Render module source or existing persisted options. This is source-proof hardening and cannot by itself validate concurrent threads or every possible world transition (requires dedicated evidence). Source-adapter Java 8/JUnit and actual HostRuntime fixture regressions are offline only. Require exact-head both-OS Foundation, full pinned Mojang 1.8.9 graphical X11+vanilla dedicated-server 78-step admission and independent unchanged-SHA second run.
