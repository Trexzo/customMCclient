# V255 — Source-owned original hurtTime and dimension getters

The host's original `playerHurtTime` and `playerDimension` callbacks were among the few local-player source reads still handled as unguarded single native getter calls. The original getter can synchronously reenter HostRuntime with a different EntityPlayerSP or null after a local player/world transition, then the older outer callback publishes its stale hurt-time/dimension value. An original hurt-time getter can also throw or supply a negative value; the original state validator throws on a negative value, but the prior host snapshot remained available, allowing a stale damage edge to influence JumpReset/DamageBoost.

V255 reuses V251's generic exact-reference original source lease with two typed wrappers. Each native callback owns one exact `Minecraft189PlayerHurtTimeAccess` or `Minecraft189PlayerDimensionAccess` original source. Nested same-source calls never consume a second tick; nested different/null source permanently revokes the older stack until the existing `finally` exits. Validate after the actual original getter and before publishing. World-unload null clears original evidence. On native exception or invalid negative hurtTime, clear the earlier snapshot and propagate the existing exception; a fresh real callback with a new player may publish. Dimension IDs are not restricted to vanilla -1/0/1 and are never invented. Neither saved config nor the original native getter is replaced, and Combat/Render/Jumper module implementations are untouched.

This is synchronous original stack ownership, NOT a claim of cross-thread atomicity or proof that separate host callbacks belong to the same player when no common original object is passed across them. Java 8/JUnit source-shaped regressions and installed real HostRuntime fixture tests are source evidence only. Require exact-head both-OS Foundation and pinned Mojang Minecraft 1.8.9 graphical X11 + vanilla dedicated server 78-step full run followed by independent unchanged-SHA full rerun. Stacked Draft child V254, no merge and main unchanged.
