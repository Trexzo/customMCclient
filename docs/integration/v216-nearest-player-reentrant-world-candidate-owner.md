# V216 — original nearest-player target selection preserves newer World-source callbacks

## Actual Java-source selection ownership gap
`Minecraft189NearestPlayerTargetState.update` scans real mapped original player positions and original World entity player/local flags; it computes squared distance and applies optional `CandidateFilter.accepts` and `CandidateScore.score` callbacks before storing a selected player index and coordinates. These callbacks are **external** to the selection state and run while the state is synchronized. Java synchronization is reentrant: a callback can legitimately invoke `target.clear()` or a nested `target.update` reflecting a newer original World/UUID/eligibility snapshot. Previously the outer loop continued and, at the end, **overwrote the newer nested selection** with the stale player from its older callback. An inner genuine invalid source could clear the target only to be repopulated by an old scan. This is a code-level source epoch issue, not a claimed reproduced game crash or server damage exploit.

## V216 actual production scope
- Increment a monotonically advancing `sourceGeneration` for every selection `update` and every explicit `clear`; this is an internal *scan ownership* token, **not a fabricated native world epoch or UUID**.
- Capture the generation before evaluating the immutable snapshots of original local player position, World player-kind flags, and entity positions. After each external `CandidateFilter` or `CandidateScore` invocation, check it is still the original scan generation. If a nested callback has cleared or selected from newer original source snapshots, stop the obsolete outer scan immediately without publishing an older target, even when the callback returns `false` or `NaN`.
- Before publishing any candidate, verify the original generation again. Keep the newest update's `available/found/entityIndex/X/Y/Z/distanceSquared` untouched if outer has been superseded.
- Preserve all prior **exact real player only**, non-local, same-source entity-count, distance minimum/maximum, stable tie, external positive finite scored policy, invalid input fail-closed, and empty real World result behavior. No fallback invented UUID, target, ray, packet, attack policy, range/3D controller or human input. An unchanged ordinary callback scan makes identical target selection as before.
- This does not by itself assert a fresh native snapshot when a callback mutates *other* World state without invoking a new target update; it only prevents losing a genuinely newer selection transition observed by this state object.
