# V208 — original Minecraft 1.8.9 AimAssist yaw/pitch setter source ownership

## Actual production source issue
`Minecraft189AimAssistModule.apply` uses legitimate native mapped `EntityPlayer.rotationYaw` and `rotationPitch` setter interfaces. Original source executes **yaw first, pitch second**, based on one physically verified original target/world/player rotation and current persisted GUI settings. Before this change, original `customMcSetRotationYaw(nextYaw)` could synchronously reenter a module disable→enable or GUI change, then the stale first activation would still execute `customMcSetRotationPitch(nextPitch)`. A GUI change disabling pitch, reducing allowed FOV, or changing permitted input during the genuine native yaw write did not invalidate the later source pitch. Additionally, the code could return success and retain its old correction interval despite native pitch callback changing the owner. This is a Java source reentrancy gap, not evidence of a reproduced Mojang crash.

## Production V208
- Increment `nativeRotationWriteEpoch` on each module onEnable/onDisable; do not allow an original setter from one activation to continue writing in another.
- Before the first actual native rotation setter, capture all **22 persisted AimAssist source controls** that can affect target eligibility/rotation math/cadence: Yaw/Pitch Speed, Require Sprint, Pause Sneak, Require Ground/Forward/Hold, Prioritize Crosshair, Min/Max Distance, Max Yaw/Pitch FOV, Yaw/Pitch Offset, Dead Zone, Yaw/Pitch Axis Enabled, Angular Easing, Easing Strength, Combined Step, Maximum Combined Step, Correction Interval Ticks. Preserve actual immutable boxed Setting values and compare all values exactly after each native setter.
- After the genuine original yaw setter returns, require unchanged module epoch, still enabled and same complete 22-value GUI policy BEFORE executing pitch. Otherwise reset only synthetic correction cadence and return false; do **not** attempt to reverse the real yaw rotation already applied in the Minecraft client. After the genuine original pitch setter, perform the same check before reporting success. The real player's input and native target/ray authority remain unchanged; a returned success never fabricates a new target.
- Keep prior validated one-axis-only operation, eligible rotated player FOV/distance gates, original smoothing, wrapped yaw, combined maximum step, native per-target correction interval, and current physical input/sprint/sneak constraints.
- Source setters that throw after partial vanilla mutation continue throwing without executing the second axis; this patch does not synthesize fake rollback of original yaw/pitch or world state.
