# V254 — Invalid original Combat list invalidates preselected target evidence

Before V254, `Minecraft189HostRuntime.worldEntityKinds` selected the nearest original player and populated aim rotation on valid original XYZ and Kind arrays. The next `worldEntityCombat` callback correctly rejected null, length-mismatched or malformed native Combat arrays, but those two invalid-data branches only cleared `worldEntityCombatState` and `KillAura.rememberSelectedTarget(null)`. They **left the previously published nearest-player candidate and target-rotation evidence in shared host state**, even though no reliable native living/hurt/team/network data existed to authorize it. Other consumers could observe the prior kind-only target after a rejected Combat sample. World-reference source checks and V252's UUID/LOS validations do not close this exact invalid-Combat branch.

V254 routes both invalid branches through the existing `rejectInconsistentOriginalCombatSource(world)` policy used for genuine UUID/LOS mismatches. That clears Combat, nearest-player, target-rotation and remembered KillAura UUID together while preserving the original World loaded-entity position/Kinds evidence for a future real sample. It does **not** synthesize a dead/unknown target, change positive Combat validation, alter the original UUID/LOS recheck cadence, disable any module, or relax the strict original game checks. Genuine malformed values remain safely rejected; the original `IllegalArgumentException` from the state validator remains caught as it was before. Native getter exceptions still propagate through the existing catch/finally original source transaction.

Regression tests install the real `Minecraft189HostRuntime`, establish actual native-shaped XYZ/Kinds with a seeded local-player position, prove that the nearest candidate and aim evidence are available **before** a genuine invalid Combat read, then require both to be unavailable for null/short/long arrays and adversarial packed hurt/team/network values. Tests also prove healthy Combat/UUID/LOS and subsequent real sampling still recover without a fake target. Tests are Java 8 offline adapters, not pinned Mojang binary proof.

V254 remains a cumulative Draft child of V253. Exact-head both-OS Foundation, pinned real Mojang Minecraft 1.8.9 X11 + vanilla dedicated-server full 78/78 and independent unchanged-SHA rerun are required. Existing historical failures remain recorded and `main` is unchanged.
