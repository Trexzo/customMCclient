## Two distinct actual source problems
`Minecraft189ReverseStepModule` only accepts an **observed original player ground→air edge** with genuine native source player motionY and optional 0–10 tick delay, physical W/A/S/D or sneak permissions. The module already consumed the edge before original motionY read and rejected a stale native getter if the module epoch or GUI settings changed. But:
1. With a positive delay, its `pendingDelay` originally **did not store which GUI speed/delay/movement/sneak policy authorized the observed departure**. Editing Speed .50→.90, Delay 3→0, Require Movement or Require Sneaking while airborne could cause an old departure to release a native Y acceleration using **new permissions or velocity** without a fresh original ground→air event.
2. After a verified original motionY getter and setter decision, the actual mapped `EntityPlayer.motionY` setter could synchronously reenter the movement host or disable→enable ReverseStep/change its source GUI policy. The older callback returned `true` even though a different activation owned the result; nested host events might also modify departure history while the outer native setter was on stack.

## Production changes
- Capture Speed, Delay, Require Sneaking, and Require Movement **at the original ground→air contact**. When its original configured delay was positive, require the complete source profile to remain unchanged before each airborne countdown/update. Any edit consumes the stale pending departure, demanding a NEW actual grounded→airborne observation. Preserve existing **zero-delay immediate source snap** and physical movement/sneak gates.
- Guard each genuine `player.customMcSetMotionY` from nested same-stack host movement callbacks with a `nativeYWriteDispatching` flag in try/finally; callback nested while an original setter runs cannot modify departure history or dispatch a second synthetic Y. The guard is deliberately not cleared by OFF→ON within the mapped setter.
- After the actual original Y setter returns, require same enabled lifecycle epoch, same source speed, configured delay and both GUI permission fields before reporting success. A setter that physically changed real Y is not fabricated back; an original setter that throws preserves its error and cannot replay the already-spent actual departure. Preserve initial mapped Y getter reentrancy ownership, original upward/no-overwrite safety, preexisting faster descent, GUI focus/suspension cancellation, input authority and no stale delayed replay.
- No artificial player motion, packets, server/world/ray, module targeting, or change to original acceptance thresholds.
