# V214 — genuine AutoSprint native setSprinting(true) cannot recursively reenter original host movement

## Actual code flaw
`Minecraft189AutoSprintModule.apply` authorizes real original mapped `EntityPlayer.setSprinting(true)` based on enabled module, genuine `Minecraft189PlayerMovementState.Snapshot`, actual W/WASD input, physical sneaking/ground/sprint state and ClickGUI focus. The existing code was a straight setter call with **no in-flight guard**. When the real mapped vanilla setter synchronously invokes the host/player movement update again, the movement snapshot provided to the nested callback can still say `sprinting=false`, so nested AutoSprint calls `customMcSetSprinting(true)` recursively before the first source mutation returns. Even if onDisable→onEnable occurs inside native setter, a new nested callback may try to write again on the same original Java stack. This is a direct source reentrancy loophole, not a claim that a live JVM stack overflow has been observed.

## V214 production
- Add an independent `nativeSprintDispatching` guard on the **genuine mapped sprint write**, not a fake movement snapshot. A nested `apply` returns without additional `setSprinting` while original external setter is on stack. Do not reset this guard on enable/disable, because OFF→ON may occur inside original callback.
- Establish the guard immediately before the real setter and release it in `finally`, including when original setter mutates genuine player sprint before throwing. Do not manufacture a rollback or forcibly switch the native sprint bit off; physical user movement retains authority.
- Preserve established no-write while the real GUI is open, optional native ground-only and W/WASD/require-forward rules, actual sneak veto, already-sprinting veto, and permission to issue a new legitimate native sprint write from a later separate real host tick. Do not replace mapped `Minecraft189PlayerSprintControl` or original keyboard snapshot with a mock at runtime.
- No cached synthetic ground state, no outgoing packet, no new timer, no fake vanilla GUI or altered movement authority. V207 native WTap setSprinting(false) logic stays independent and retains its separate source epoch and cooldown checks.
