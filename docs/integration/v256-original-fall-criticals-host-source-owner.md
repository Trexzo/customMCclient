# V256 — One original fallDistance owner across NoFall and Criticals

The host previously invoked NoFall's independently guarded mapped native fall-distance getter/setter and then read `player.customMcFallDistance()` again to produce `Minecraft189CriticalsEvidence.fall`. This second native getter did not have its own host source ownership. Even if NoFall was disabled, the mapped original getter could synchronously reenter the host for a replacement original player or null/world unload, after which the old outer player could publish stale Criticals fall evidence. A native getter exception also left the previous Criticals fall flag unchanged.

V256 pins one original `Minecraft189PlayerFallDistanceControl` for the complete host NoFall→Criticals callback through typed V251 `Minecraft189ExactSourceLease`. Nested same-player callbacks never create another tick; changed/null nested player irreversibly revokes the outer lease. The wrapper delegates genuine fall getter; each native NoFall setter is allowed only while same source remains owned and the actual GUI does not have focus. Following NoFall, a separate genuine fall readback is published only if the original lease remains owned through that second getter. A null source, source replacement or mapped native exception marks the Criticals fall source UNAVAILABLE via existing `criticalsEvidence.fall(Float.NaN)` (the existing source validator sets `fallKnown=false`) instead of leaving stale positive evidence. A real NoFall setter that writes and then throws is **not rolled back**. Existing NoFall's native read-epoch, threshold and options are preserved; no movement/Combat/Render feature module changes.

The host lease does not fabricate criticals motion evidence, nor does it claim to make physically changing fallDistance values immutable or solve concurrent-thread races. Criticals requires independently sampled real fall and motion evidence, as before. Java 8/JUnit source regressions use installed HostRuntime and genuine-shaped native callback adapters, not the official Minecraft binary. Exact-head Windows+Ubuntu Foundation, original Mojang 1.8.9 graphical X11 with vanilla dedicated server 78/78 and independent unchanged-SHA second 78/78 remain mandatory. Draft cumulative child V255; no main changes, no merge.
