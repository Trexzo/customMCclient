# V227 — AirJump original mapped jump() same-stack ownership

The verified AirJump implementation samples physical Space only in the outer finally after original `EntityPlayer.jump()`. A real mapped native jump may reenter the movement host before that finally executes; without a separate same-stack dispatch guard, a nested call could re-use the unconsumed Space edge, including after ON/OFF or for another original player.

This release installs `nativeJumpDispatching` around actual `customMcJump()` and clears it in a dedicated finally block even if the genuine source writes original motion then throws. The guard is not reset in onEnable/onDisable, so nested module restart cannot double-jump. It does not take over the physical Space edge: the already verified outer-epoch finally behavior survives unchanged. In particular an accepted original jump that releases Space within its mapped callback still counts, and the next new physical Space press can jump; the old activation may not overwrite a fresh re-enabled key owner. Existing real onGround and GUI focus veto are maintained.

They are source-adapter evidence, not authentic binary evidence.
