# V232 — AirSpeed native original X/Z getter and setter owner

AirSpeed's production callback already demanded genuine original movement availability, airborne status, source rotation, physical WASD and exact speed/smoothing settings, rechecking an epoch after native X and Z reads and after original X setter. Those checks did not prevent a synchronous original player callback from replacing the source player, suspending the host or presenting newly grounded or unknown actual movement while the outer callback still wrote stale X/Z. They also did not stop nested same-player mapped getters/setters from spending a second callback during the same stack.

V232 adds a single `nativeMotionDispatching` transaction pinned to one original mapped player across `motionX` getter, `motionZ` getter, and both original X/Z setters. Nested callbacks cannot double-read/write. Different native player, module disable, suspended owner, missing original rotation, unknown or grounded source revoke outer permission; all original X/Z read/post-X checks now test this revocation in addition to the prior native lifetime, four physical WASD states, speed and acceleration GUI settings. An original X setter that revokes permission cannot be followed by obsolete Z. The returned result is revoked if Z setter changes the source. Exceptions release this guard without pretending to undo genuine player velocity changes.

Existing actual-only-airborne gate, default speed 0.35, diagonal normalization, original source-smoothing interpolation and nonfinite repair, W/A/S/D direction, 3 live settings and precedence with Flight/Strafe are preserved.

JUnit original-shaped native regression tests are offline source-adapter proof only. Require exact SHA Windows+Ubuntu Foundation, real pinned Mojang Minecraft 1.8.9 graphical X11 + vanilla dedicated-server 78-step original suite and independent unchanged-SHA second run before admission. Draft child of V231. Never inherit parent native results or alter main.
