# V212 — original Jitter external randomized interval and strength callbacks cannot emit a stale vanilla rotation

## Actual source gap after V209
V209 `Minecraft189JitterModule` added an epoch + exact 13-setting GUI policy snapshot immediately **before** real mapped yaw/pitch setters and revalidated after each. But Jitter's optional `DoubleSupplier.getAsDouble()` for **random interval** and separate **yaw/pitch variable strength** runs BEFORE that snapshot. The supplier is external code and may synchronously reenter `onDisable/onEnable` or edit enabled axes, source requirements, random amplitude and correction interval. The old activation could then finish calculating the original stroke and snapshot the NEW activation after the stale supplier had already run; yaw and pitch would be applied to real player even though no longer authorized by the source when sampling began. This is a direct Java source reentrancy gap; no live Minecraft exploit, native crash or packet bypass is asserted.

## Actual production V212 fix
- Capture `nativeRotationEpoch` plus **all original 13 persisted Jitter settings** BEFORE optional `sampledInterval`, rather than immediately before native setters.
- Require same exact live module owner/GUI policy **after the optional interval supplier**, **after sampled outward yaw strength** and **after sampled outward pitch strength**. This prevents a later source sample or any genuine `customMcSetRotationYaw/Pitch` if the owner/policy was changed by previous supplier callback. Cancel only synthetic cadence/paired return, no artificial player rotation rollback.
- Keep V209 revalidation after each actual mapped vanilla yaw and pitch setter; now source permission spans the entire RNG computation **and** both native original rotation callbacks.
- Retain default fixed-mode behavior (never call RNG when random modes disabled), previously validated 1–10 tick interval range, outward/return pairing with exact float deltas and clamped pitch, physical right/left mouse, ground/sneak permissions, target/world source and one-axis config. No invented player yaw/pitch, packet or new acceptance bypass.

## Tests and certification
Fourteen new offline JUnit original source `DoubleSupplier` callback tests: random interval disables module, OFF→ON, edits interval variation or pitch axis; random outward yaw strength disables, restarts or changes pitch policy and must not even consume old pitch RNG; second pitch strength disables or edits variation; combined interval/strength second sample editing Hold; fixed mode never invokes RNG; normal exact paired return and full native dual-axis action; a fresh original activation may start a new valid stroke after an aborted random source callback. These tests use genuine Java mapped rotation interface adapters, **not** an actual Mojang GUI runtime binary.
