# V250 — Original loaded-world identity through kinds, combat, LOS and UUID rechecks

V249 pins LOS, UUID and XYZ getters within `worldEntityPositions`, but the subsequent independent `worldEntityKinds` and `worldEntityCombat` callbacks were not required to belong to that same original World object. Both also invoke genuine mapped getters capable of synchronously reentering the host. An old-world kind array or combat array could therefore be paired with another world's XYZ/UUID/LOS; reentrancy could allow the old outer host to publish target data after the world source changed.

V250 records the exact original World supplied by a successfully published V249 XYZ source sample (`tickOriginalEntityWorld`). A new admitted positions sample invalidates prior kinds before any downstream callbacks. Kinds and Combat must use that same original Java World instance and a current available XYZ snapshot; they each get a source-owner `Minecraft189WorldEntityDownstreamSourceLease` around the mapped native getter stack. A nested same-world callback is not a second tick; a different or null nested original world irrevocably revokes the active source. Validate after genuine Kinds, UUID recheck, LOS recheck and Combat getters, and after target selection. On source mismatch/revocation clear position/kinds/UUID/LOS/combat, transient world handles and remembered target identity rather than publish any mixed entity evidence. A malformed original kind/position is not cached for a later tick; actual native exceptions propagate. Existing deliberately caught UUID/LOS RuntimeException fallback and required identity consistency remain preserved. Genuine invalid combat arrays still fail closed.

The original World reference does not prove loadedEntityList order is immutable during three getter calls; validating a list-generation/UUID-order transaction remains a separate requirement. V250 changes common HostRuntime source ownership, not individual KillAura or Render module production algorithms. New Java 8 JUnit source-adapter and real HostRuntime integration tests are offline evidence, NOT original binary verification. Exact-head both-OS Foundation, pinned Mojang Minecraft 1.8.9 X11 graphical/vanilla dedicated-server full 78-step acceptance and independent unchanged-SHA second original run remain mandatory.
