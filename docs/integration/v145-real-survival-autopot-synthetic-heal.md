## Why this is stronger evidence

V143 verified actual original source pitch mapping and real AutoPot right-click eligibility but not a cast. V144 verifies **manual physical X11 right-click** can really create a native Regeneration effect. V145 now connects the **genuine production AutoPot module's synthetic rightClickMouse** to an independently observed **Survival-mode source health increase**. No fabricated health, Java PotionEffect, test-source ItemStack, fake packets or physical manual throw can satisfy it. A failed original client cast, low-health gate, wrong native item, missing healing, changed same-player identity or failure to restore currentItem makes the official job fail.

Evidence boundary: Integrated original vanilla client/server world health increase and one production synthetic rightClickMouse, not an automatically inferred multiplayer remote dedicated server impact, packet-level server trace, real-world medical effectiveness, or guarantee every combat potion hits. Natural healing is unlikely to explain a rapid >=4 source health rise, but a formal dedicated-server potion-entity ownership/damage provenance test would be an additional later gate.
