# V215 — real mapped player X/Z speed HUD: finite Euclidean distance and overflow-safe availability

## Real Java source bug
The original `Minecraft189MovementSpeedTracker.sample` receives actual mapped finite player X/Z positions, subtracts successive positions, computes `Math.sqrt(deltaX * deltaX + deltaZ * deltaZ) * 20` and exposes `blocksPerSecond` + max `peakBlocksPerSecond` to the visible speed HUD. For **finite representable** deltas (e.g. x=1e200 and z=0), squaring x itself overflows binary64 to Infinity, even though the true 20-ticks-per-second Euclidean speed **2e201 is finite**. The old implementation marked `speedAvailable=true` and published `Infinity` to HUD, only suppressing updates to peak. Independently, delta subtraction of two extreme valid finite positions and the final multiply by 20 may genuinely overflow; the old HUD still published Infinity. This is directly demonstrated by Java floating-point arithmetic and the actual production tracker source, not a claim that vanilla Minecraft gameplay normally reaches 1e200 coordinates.

## Production correction
- Use `Math.hypot(deltaX, deltaZ)`, which computes a numerically stable horizontal Euclidean norm without premature overflow from squaring finite mapped deltas. Multiply the finite geometric distance by the unchanged `20.0D` ticks/sec conversion; no new smoothing, source movement multiplier, player motion setter, packet or invented X/Z coordinates.
- Set `speedAvailable` only if the **complete computed blocks/sec sample** is finite. If the actual extreme mapped sample cannot be represented (finite input, overflowing subtraction or ticks/sec conversion), display no current source speed (`available=false`, numeric placeholder 0) instead of showing Infinity. Do not update the peak. Retain the current source position as the next baseline so a later genuine representable delta can recover rather than replaying huge stale coordinates.
- Preserve a valid physically stationary zero as **available speed=0**, original 3-4-5 Euclidean speed of 100 blocks/sec, existing peak semantics, first-sample unavailable baseline, negative/signed-zero source positions, `clear()` resets, and preflight rejection of native NaN/Infinity X/Z before any state mutation.
