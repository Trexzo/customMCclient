- Issue exactly one ephemeral native-use completion ticket through `beginAutoBlockNativeUse()` only after the existing sword/real target/UI/manual-input/slot gating succeeds and **before** the real mapped `customMcRightClickMouse()` call.
- `Minecraft189AutoBlockModule` tracks the activation epoch, token, captured Hold Ticks and Pause Manual Right policy. Increment epoch/revoke uncommitted token on every enable/disable and shutdown, but preserve a previously **actually owned** native block for the existing legitimate release callback.
- After actual original right click returns, require genuine `isUsingItem` confirmation, re-read the **actual source-held sword** and current ClickGUI/manual right mouse state in `Minecraft189HostRuntime`, and call `completeNativeUse(token,...)`. Only the same activation/token + unchanged persisted policy + genuine sword + no GUI/manual takeover may mark the block as owned. A completion is one-shot even if it is vetoed; a newer token invalidates the older pending right-click.
- Normal original `shouldStop` / `releaseForAction` continue preserving real user-held right mouse input; the legacy isolated `started()` is retained for older direct test setup but is **not called by the true Minecraft right-click pipeline**.
- Does **not** claim to undo the actual server/client use action when native right-click already completed before policy revocation: it prevents false synthetic *ownership tracking* after reentrant state changes. No invented game objects, packets, native changes, or alternate controller authorization.
