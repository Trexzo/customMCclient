# V231 — Strafe original native X/Z reentry and player ownership

Strafe's previous mapped original motion X/Z adapter had strong epoch, speed, smoothing, physical WASD, onGround and sneaking source-eligibility checks. It did not own the full same-stack native `motionX/motionZ` getter/setter pair. Original mapped setters and getters can synchronously reenter the movement host before vanilla values advance, allowing a callback with another original player, suspension, lost rotation, onGround change or opted-in sneaking to leave the earlier X/Z callback permitted to write a stale Z axis.

V231 pins one `Minecraft189PlayerMotionControl` with `nativeMotionDispatching` across original getter X, getter Z, setter X and setter Z, clearing the lease in try/finally without inventing rollback if native setters throw after changing vanilla velocity. A nested same-player source cannot read/write a second time on that stack; changed original player/rotation or nested suspended/ground/sneaking disqualification revokes outer native source permission. Existing `nativeMotionOwned` validates this cancellation after X getter, after Z getter and after X setter before any stale Z, while retaining the original epoch, persisted 5-setting snapshot, physical WASD keys, direct/smooth interpolation, normalized diagonals and legacy unknown-source opt-in policy. A callback from Z setter is contained by the guard and cannot borrow another original player's velocity.

Offline Java 8/JUnit adapter tests include genuine-shaped native X/Z getter and setter recursion, second player, disabled/re-enabled source, suspension, ground/sneaking veto, physical key/policy change, partial native exception, smooth acceleration and preserved GUI priorities. The source-adapter tests are not genuine Mojang binary proof. V231 requires exact-head Windows+Ubuntu Foundation, full genuine pinned Mojang 1.8.9 graphical X11 + vanilla dedicated server 78-step acceptance and independent unchanged-SHA original rerun.
