# Provenance and clean-room policy

This is a ground-up implementation.

Donor projects may be studied to identify responsibilities, behavior, UX ideas, performance constraints and failure modes. Implementation is not copied from:

- recovered or decompiled proprietary clients;
- cracked binaries or packages;
- GPL/copy-left projects into a permissively licensed core unless that licensing decision is explicitly changed;
- source whose authorship or rights are unclear.

Repository-level licenses do not automatically make embedded third-party code, Minecraft source, assets, fonts or textures reusable.

When a donor materially informs a subsystem, the design documentation should record the concept being reproduced and the independent implementation boundary.

Minecraft/Mojang source and binaries are never committed as project source.
